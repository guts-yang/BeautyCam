## 当前结论

已删除固定鼻子/嘴唇椭圆排除，移除最终面部椭圆裁剪与直角恢复域。鼻梁、鼻尖、侧脸和下颌不再被这些固定区域强行排除。**当前仍未达到原课程M1 IoU门槛，不能验收或合并为最终版。** 测试通过、示例改善和辅助统计均不能替代该要求。

## 实际改动

M1首轮仍以三路确定性GMM/图割共识定位主体，连续模式不把ROI外肤色混入初始背景GMM。第二轮以首轮实际预测作为确定前景与模型样本，在主体的圆滑邻域内重新图割，重新判断初始椭圆外的皮肤；不使用样本ID、GT或预训练模型。邻域由当前主体形状生成，向下补下颌、向上仅小幅扩展。颜色及初始居中肖像定位先验仍存在，不能宣称任意构图的人脸解析。

眼眉保护来自局部暗残差和横向结构，只用显著深于皮肤中位亮度的暗结构，避免把眼下正常皮肤阴影排除。嘴唇保护来自局部红色对比与连通域，参考首轮主体定位，防止颈部扩展改变五官搜索位置。只保留与最强唇色候选相邻的上下唇，避免把鼻尖、下巴泛红或皱褶当嘴唇。此方法仍是近似，未获得精确关键点或语义分割。

M2在皮肤内部通过归一化高斯估计缓变亮度，在亮度基底上执行CLAHE与自适应曲线，再把平滑曝光增量加回原始纹理；不直接放大每个毛孔的局部对比。外轮廓羽化半径为图像短边3%，内部眼唇/小孔为0.5%，避免小缺口扩大成大片提亮不足；保留最大增益及实际BGR过曝预算。M4的highpass_gain由0.8改为1.1，避免磨皮后再次压低细节。M3代码和配置未改。

新增参数仅在B的skin_detect.yaml和exposure.yaml，M4只调整既有值。冻结函数接口及0/255、BGR uint8契约保持；算法无文件读写、跨模块import、预训练模型或全局RNG操作。未修改A/C实现、依赖或CI。

## 复现

在仓库根目录、依赖环境中使用新的输出目录：

```powershell
pytest -m "not integration" -q
python tools/evaluate_m1.py --output results/m1_new_run
python tools/evaluate_m2.py --output results/m2_new_run
python tools/evaluate_m4.py --output results/m4_new_run
python tools/evaluate_b_composite.py --output results/composite_new_run
python tools/benchmark_b.py --output results/timing_new_run
```

待复测算法时固定代码/配置后再运行；计时应单独执行。原协议评测未达标时退出码1是有效失败记录，不是评测工具故障。
