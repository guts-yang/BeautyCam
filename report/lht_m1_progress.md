## 可复现命令

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest -m "not integration" -q
.\.venv\Scripts\python.exe tools/evaluate_m1.py --data-root data/input/subset
```

第一条以及直接运行 pytest 的结果均为 71 passed, 1 deselected。未选择的是原有数据集 integration 用例；实际 40 张指标由第二条独立测量，不把前置条件检查当作算法验收。

第二条在指标未达标时返回退出码 1，同时完整保存真实结果；这不代表程序崩溃。每次默认创建新结果目录；显式 --output 指定的目录必须尚不存在。

本次只运行了 Python 3.12，本地未验证 3.10；后续 PR 由现有 CI 的 3.10/3.12 矩阵复核。

- 使用版本管理清单 assets/evaluation_manifest.csv 的同一批 40 个 ID。
- 最小子集来自项目指定镜像，只按 HTTP Range 读取指定条目；传输约 53.9 MB，没有下载完整数据包。

- 按 prepare_data.py 的组件索引顺序合并 GT，skin_gt 是合并标签 == 1。原图 1024×1024，512×512 GT 使用最近邻对齐。
- 原始清单未修改，scene 仍为未经人工核验的占位标签；本次不宣称已实现五类真实场景分层。
- M1 只接收图像与配置；GT 仅传入离线计分函数，不参与预测。
- 40 张均有有效皮肤 GT，没有剔除困难样本。图像宏平均，每张图等权。

## 失败分析与后续重点

面板显示高召回主要来自偏宽的颜色候选域。相近色度的头发、背景、耳颈和手也会被判为皮肤，而当前 GT 只认合并标签中的 skin 类，并排除了鼻子和其他独立组件。

代表样本 12711、25204、27861、9879 中，头发或背景的大块误检拉低 IoU。对低照度/肤色差异样本，也仍存在漏检。简单开闭运算与小区域清理只能处理小噪点，不能去除与脸部同色且相连的大区域。

额外做了同一 40 张上的开发用矩形阈值网格诊断：5544 组候选中，满足原始掩码 Recall ≥0.80 的最好结果约为 IoU 0.502830、Recall 0.803117，对应 Cr 144–170、Cb 80–120。它仅是这次网格搜索的结果，不是算法上限，也不是独立留出集验证；尚未将候选参数写回 YAML。

下一轮应优先研究传统空间/形状约束，减少大块误检，并保留低照度样本的召回；需要新增可调参数时，先由 A 按冻结 schema 的变更流程确认。不能用 GT 裁剪预测、不能加入预训练人脸模型，也不能直接放宽 0.75 验收线。
