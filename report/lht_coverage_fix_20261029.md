# M1覆盖与M2曝光融合修复

整理及源码一致性复核：2026-10-29。负责人：B / qixing1227；分支：lht；关联：[PR #52](https://github.com/guts-yang/BeautyCam/pull/52)，#17–#20；完整验收入口：[lht_acceptance.md](lht_acceptance.md)。原始评测产物批次名保留20261022。

## 问题与原因

旧提交8def1d2已通过测试和模块隔离定量门槛，但实际M1预测掩码驱动M2–M4时，6277出现阴影面颊/下颌漏检，以及局部提亮的明显边界。此前验收缺少对真实组合输出的检查，不能凭隔离指标和CI声称画面已达要求。

M1可信分支的背景GMM训练集合包含整个初始ROI外区域，其中可能含有真实皮肤，阴影区域因此更容易被判作背景；最终固定面部椭圆又裁掉部分面颊和下颌。M2直接按二值掩码应用曝光增量，在掩码边界产生亮度跳变，放大了分割缺口。

## 修复后的行为

M1保留原三路共识，再对两个可信BGR分支分别增加背景模型纠偏版本：背景训练样本只取非肤色候选，不把ROI外全部像素强行作为背景训练样本。共五路分割，仍采用确定性GMM及冻结模型图割，不引入随机初始化或预训练模型。

恢复域依据三路共识主体的坐标分布生成，默认自纵向55%分位以下恢复，横向按主体1%–99%范围外扩25%；只接纳纠偏分支的候选，不直接填充整个几何区域。配置spatial.face_ellipse为null以取消最终固定整脸裁剪。初始种子ROI和鼻/唇保护椭圆仍存在，不能称为无几何先验的人脸检测或关键点定位。

M2新增可选mask_blend：以掩码内部距离变换生成平滑权重，默认渐变半径为短边3%，曝光增量补偿最多2倍。外部像素保持原样，原有最大增益、实际BGR过曝预算仍生效。窄碎片不会因无限补偿重新产生硬亮边。

新增参数只在B自有skin_detect.yaml和exposure.yaml。冻结接口及掩码契约不变，不修改A/C模块、依赖或CI。缺少新配置块时恢复功能默认关闭、融合半径为0；当前YAML的--no-clahe对照仍保留融合，不能把它描述为与旧硬掩码输出逐像素相同。

## 量化结果与证据范围

同一固定40张、原始1024×1024输入、512×512 GT最近邻对齐。没有剔除失败样本，没有独立留出集；全部40张参与校准。

| 测量 | 旧提交8def1d2 | 当前修复版 |
| --- | ---: | ---: |
| 6277皮肤IoU | 0.620323 | 0.823023 |
| 6277皮肤Recall | 0.655725 | 0.902467 |
| 40张M1 IoU宏平均 | 0.752331 | 0.750621 |
| 40张M1 Recall宏平均 | 0.876024 | 0.904548 |

覆盖率提升伴随IoU轻微下降，不能称为所有指标提升。当前M1后处理关闭IoU 0.750161，开启0.750621，变化+0.000460；IoU≥0.75、Recall≥0.80、后处理下降不超过0.02三项通过，但IoU仅略高于门槛。

M2仍使用相同GT区域做隔离统计，唯一真实欠曝样本6277提亮20.8184%，输出过曝比例0，达到≥15%和≤1%的量化要求。真实欠曝样本仅1张。原本过曝的5118仍保留，未宣称修复其既有高光问题。

新增tools/evaluate_b_composite.py使用M1预测掩码完成全部40张M1→M2→M3→M4，再读取GT计算覆盖率；不把GT或样本ID传给处理模块。保存所有输出、掩码、对照图和统计，并检查输出格式及掩码外像素不变。

在6277相同新版预测掩码上，硬掩码曝光控制组的内侧一像素边界新增亮度平均16.445、P95为28；融合版该边界平均/P95为0。此测量排除了原图固有边缘，只说明新增亮度在这一圈像素上的变化，不能推导整幅图无伪影或两人视觉评分合格。空/全掩码没有内部边界时报告None，避免伪造0分。

2026-10-29复核当前源码及配置与M1、M2、完整组合、计时摘要中的哈希一致；正式M1评测和实际组合评测的40张掩码逐像素相同，3张展示图也与组合产物一致。原图和派生图仅在本地被忽略的results/保留，不上传GitHub。
