# B：Haar辅助定位与连续皮肤修正

图像评测于2026-10-31完成，交付记录于2026-11-09更新。qixing1227 / lht，[PR #52](https://github.com/guts-yang/BeautyCam/pull/52)。

本轮按用户“允许传统Haar检测器，不使用深度学习”的明确授权实施。Haar是传统预训练级联模型，属于对原基线“任何预训练模型均禁止”的特定例外，不宣称无模型；A仍负责最终评审与合并。

## 改动与原因

原分割仅靠颜色及居中肖像先验，会选中头发、颈部，并把高光/阴影留成皮肤空洞。现在用两种Haar人脸级联的一致框、合理配对的眼睛确定局部搜索域；在图像中追踪发际与下颌边缘，限制肤色误选。对可信定位中的闭合空洞恢复皮肤，按实际眼部框、局部眉毛暗结构和唇色保护五官。无固定鼻子排除区，也不使用GT参与推理。检测不可靠时保留原分割。最终再执行形态学和小连通域清理，避免清理后又生成细碎边缘。

人脸框只是粗定位，眼孔、面部支持域与边缘搜索仍是近似；当前没有像素级预训练人脸解析器、深度学习或商业修图能力的保证。遮挡2313等低分案例保留，不能仅凭均值证明每张脸完整。

M2–M4代码与配置本轮未改：曝光调整缓变亮度并保留原纹理；双边平滑和轻量频域细节回注继续按实际M1掩码执行。

## 模型来源、许可与接口

来源：本机opencv-python-headless 4.10.0.84自带OpenCV 4.10.0的cv2/data/haarcascades。上游对应路径为[OpenCV 4.10.0 Haar数据](https://github.com/opencv/opencv/tree/4.10.0/data/haarcascades)，原理参考[OpenCV级联分类器文档](https://docs.opencv.org/4.x/db/d28/tutorial_cascade_classifier.html)。模型原始完整XML含Intel许可，无损zlib/base64嵌入B的skin_detect.yaml；另附[lht_haar_models_LICENSE.txt](lht_haar_models_LICENSE.txt)。以下SHA256对应本地实际封装字节，未声称独立校验上游下载字节。

| 原模型文件 | SHA256 |
| --- | --- |
| haarcascade_frontalface_default.xml | `0f7d4527844eb514d4a4948e822da90fbb16a34a0bbbbc6adc6498747a5aafb0` |
| haarcascade_frontalface_alt2.xml | `7b0c967d9abbdfbde025eb9c786947d151b6426040d07a8f9562ed8fd90724b4` |
| haarcascade_eye_tree_eyeglasses.xml | `e32f9c67935c33e9d1331eb14fa58554ff17835c03742663bcb97a892e936a57` |

运行时仅从cfg解码，核对SHA256，使用FileStorage的MEMORY模式和CascadeClassifier.read；模块不读取路径、不下载、不持有全局模型或缓存、不操作全局RNG。打包工具tools/package_haar_config.py只供离线重新生成配置；配置缺少face_locator或enabled=false则兼容旧行为。冻结签名、BGR uint8及0/255掩码不变，A/C目录和依赖不改。
