焕颜相机（BeautyCam）分工认领 + 开发规范

【1｜项目是什么】
《数字图像处理》课设，第 4 题「人脸美颜相机——肤色保护与细节增强」。
用 Python + OpenCV + NumPy 做一条 7 模块的图片美颜流水线，全程传统图像处理，禁止深度学习。
仓库：github.com/guts-yang/BeautyCam，已建好 8 个 Epic + 27 个 Issue，直接认领即可。

【2｜三个板块，各管一块，互不打扰】
板块一 平台与编排（A，@guts-yang，分支 lcy）
  主流程串联、配置、命令行、演示界面、测试与 CI

  对应 Issue：#25 ~ #31

【3｜为什么不会互相拖后腿】
一，一人一个目录、一人一套配置文件，不存在两个人改同一个文件。
二，模块之间只通过「冻结的接口」通信，不允许互相 import。
三，A 先把接口、配置、掩码格式定死（Issue #10），B、C 当天就能同时开工，不用等别人写完。
四，联调只在最后统一做，不是边做边等。

【5｜代码提交规范（请照做）】
第一步，永远不要直接在 main 上写代码。
第二步，先拉一条属于你自己的分支，分支名就是你的名字简称：
  A（guts-yang）用 lcy，B（qixing1227）用 lht，C（Shiqi0502）用 lsq
  git checkout main
  git pull
  git checkout -b 你的简称
  例如：git checkout -b lcy
第三步，之后所有开发都在自己这条分支上做；这条分支长期用，不要做完一个 Issue 就删。
第四步，只做指派给你的 Issue，不要顺手改别人的文件。
第五步，提交前本地跑一遍测试：
  pytest -m "not integration"
第六步，推送分支并发起 PR 到 main：
  git push -u origin 你的简称
  PR 标题写：【你的简称】Issue 编号 + 一句话
  PR 描述里写：Closes #编号（例如 Closes #19）
第七步，PR 交给 A（guts-yang）统一 review 和合并；CI 不通过不允许合并。

【6｜三条红线】
一，不要改 core/、io/、config/pipeline.yaml、requirements.txt、.github/（这些是 A 的）。
二，模块之间禁止互相 import，跨模块只能由主流程调度。
三，模块内部不要读写文件、不要用全局变量。
