## 1. 用途与总原则

本文件规定 UI/UX 视觉与交互红线，以及算法代码层的设计原则。UI Token 与交互规则适用于本地演示界面；模块职责、接口、数据契约和目录结构以 [arch.md](./arch.md) 为准。

设计优先级：让用户清楚比较原图与处理结果；不遮挡图像细节；状态、错误和键盘焦点可识别；处理模块相互独立，仅通过编排层协作。

## 2. UI/UX 设计系统

### 2.1 视觉定位与色彩 Token

视觉定位为“温暖自然”：米白背景、肤粉强调色、深棕正文。下表为候选值，仍需基线确认。浅肤粉强调色上使用深色文字，不使用白字。

| Token | 用途 | 候选值 |
| --- | --- | --- |
| `--bg-base` | 页面底色 | `#FAF7F4` |
| `--bg-surface` | 卡片/控件表面 | `#FFFFFF` |
| `--text-primary` | 主文本 | `#2B2622` |
| `--text-secondary` | 次级文本 | `#6B6259` |
| `--accent-primary` | 主强调/按钮背景 | `#E8A598` |
| `--accent-hover` | 悬停背景 | `#D98E80` |
| `--accent-active` | 按下背景 | `#C57A6C` |
| `--text-on-accent` | 肤粉按钮文字 | `#2B2622` |
| `--border` | 非交互装饰分隔线 | `#E6DFD8` |
| `--border-strong` | 输入框/交互控件边界 | `#8A8178` |
| `--focus` | 键盘焦点环 | `#0B2E59` |
| `--success` | 成功状态背景 | `#3E7857` |
| `--success-foreground` | 成功状态文字 | `#FFFFFF` |
| `--danger` | 错误状态背景 | `#B23A48` |
| `--danger-foreground` | 错误状态文字 | `#FFFFFF` |

色彩验收规则：

- 一般文字与背景对比度至少 4.5:1，大号文字至少 3:1；有意义的控件边界和焦点指示至少 3:1。
- 按 WCAG 相对亮度算法核算的候选组合：主/次文字对页面底色约 14.02:1 / 5.60:1；肤粉/悬停/按下背景上的深色文字约 7.32:1 / 5.80:1 / 4.54:1；焦点色对页面底色约 12.70:1、对肤粉/悬停/按下背景约 6.63:1 / 5.25:1 / 4.11:1；成功/错误白字对状态底色约 5.21:1 / 5.85:1；强边界对页面/白色表面约 3.58:1 / 3.82:1。
- `--border` 仅作装饰，不单独承担输入框或控件边界；交互边界使用 `--border-strong` 或满足对比度的组合。
- 不得只靠颜色传达成功、错误、选中状态，须同时提供文字或形状提示。
- 新增颜色须先登记 Token 并核对实际前景/背景组合；不得默认使用肤粉背景配白色小字。

### 2.2 字阶与字体

采用五级字阶：

| 级别 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| XS | 12px | 18px | 400 | 辅助说明、文件信息 |
| SM | 14px | 22px | 400 | 正文、表单标签 |
| MD | 16px | 24px | 500 | 控件文字、次级标题 |
| LG | 20px | 28px | 600 | 区块标题 |
| XL | 24px | 32px | 700 | 页面标题 |

只使用以上字号及 400/500/600/700 字重。界面最多使用两种设计字体；中文/英文系统字体回退不计为额外设计字体。响应式缩放如需不同尺寸，先更新字阶 Token，不得局部任意加字号。

### 2.3 间距、圆角与图像布局

- 间距基数为 4px，优先使用 4/8/12/16/24/32px。
- 普通控件圆角 6px、卡片 10px、弹出面板 12px。
- 原图和结果图须保持相同显示比例并标注清楚；不得为填充区域而拉伸或裁切关键脸部区域。
- 对比视图应能明确辨认“原图/处理后”；图像优先于装饰元素。
- 控件须有清晰标签和当前值；滑块支持键盘调整；上传失败、处理状态、错误原因均须有可读文字。

### 2.4 交互状态

原定五态保留，并补充键盘焦点和表单错误状态。按控件能力适用，不要求静态图像面板具备按钮的全部状态。

| 状态 | 约束 |
| --- | --- |
| 默认 Default | 显示名称、当前值和操作提示 |
| 悬停 Hover | 支持悬停的控件有可辨变化；可用 `--accent-hover`；不得依赖动画传递信息 |
| 按下 Active | 按钮有按下反馈；可用 `--accent-active`，不得仅靠位移表达状态 |
| 禁用 Disabled | 禁止触发操作并说明原因；不得整体降低不透明度到文字难以阅读 |
| 加载 Loading | 仅表示实际耗时/异步操作；明确显示处理中并防止重复提交 |
| 键盘焦点 Focus-visible | 所有可键盘操作控件显示清晰焦点环；不得移除焦点样式而无替代 |
| 校验错误 Error | 上传/配置错误提供具体原因与恢复方法，并以文字和视觉状态共同提示 |

### 2.5 Streamlit 落地约束

- 使用 Streamlit 原生布局和控件；优先通过 `.streamlit/config.toml` 主题配置落实背景、强调色和字体。
- 若原生主题无法实现深色文字在浅肤粉按钮上的对比度等要求，可用局部自定义 CSS；CSS 必须引用 Token、限定作用范围，不得依赖随机生成的内部 DOM 类名。
- 不得为像素级还原而破坏键盘操作、上传校验或错误提示。
- 处理为同步且很快时，不得伪造持续 Loading 状态；只有实际处理期间才显示加载反馈。
- 图像在本地运行环境处理；上传输入不自动复制到长期存储。需要保存的结果由用户明确触发保存/导出。

## 3. 算法与代码层设计约束

### 3.1 解耦目标

**降低模块间耦合度是硬性设计目标**：模块不直接调用或导入其他处理模块；跨模块流程只由 `core/pipeline.py` 编排；算法模块保持纯计算，不通过磁盘文件互相传递状态。

### 3.2 拟定接口与模块职责

M1、M5、M7 与图像变换模块职责不同，不强制使用同一返回类型。以下接口是草案，具体参数和记录结构以 [arch.md](./arch.md) 第 5 节为准：

```python
def detect_skin(image_bgr, cfg):
    """M1：BGR uint8 图像 -> 同尺寸 uint8 皮肤掩码，取值 0/255。"""

def process(image_bgr, skin_mask, cfg):
    """M2/M3/M4/M6：图像与掩码 -> 新的 BGR uint8 图像。"""

def get_frequency_diagnostics(image_bgr, cfg):
    """M4 可选诊断：返回同尺寸 BGR uint8 低频图与高频可视化图。"""

def restore_motion_blur(image_bgr, cfg):
    """M5：BGR uint8 图像 -> 新的 BGR uint8 图像；不依赖 M1。"""

def compute_image_metrics(stage_input_bgr, stage_output_bgr, regions,
                          reference_bgr, predicted_skin_mask, cfg):
    """M7：对可用阶段图、GT 与参考图计算指标，返回记录；不做文件 I/O。"""

def summarize_survey(responses, cfg):
    """M7：匿名问卷记录 -> 汇总统计；不读写文件。"""
```

接口与数据规则：

- 图像统一 OpenCV BGR、`uint8`、`H×W×3`；掩码为同尺寸 `uint8`、0/255。
- 处理函数不得原地修改输入；输出图/掩码必须为新数组并符合尺寸、类型契约。
- M1 只产出运行时皮肤掩码，不负责调用后续模块。
- M2/M3/M4/M6 通过参数接收 M1 掩码，不读取 M1 的全局变量；掩码为空时按架构约定安全跳过肤色限定操作。
- M3 运行时只依据皮肤掩码、保边滤波和局部异常信息，不假设存在人脸关键点/五官分割；五官 GT 仅用于离线评价，不参与运行时模块依赖。
- M5 不依赖肤色掩码；M7 只做指标计算/问卷统计，不读文件、不写 CSV、不调用其他算法模块。
- `core.pipeline` 显式传递数组；`io` 负责读写；UI/CLI 只调用稳定的流程入口。磁盘是持久化边界，不是模块解耦的通信机制。

### 3.3 依赖方向与文件责任

- 允许依赖方向：CLI/Streamlit UI → core → modules / metrics / io。
- M1–M6 模块彼此禁止 import；M7 不 import 图像处理模块；算法模块不依赖 UI、CLI、文件系统或 core 私有状态。
- 每个模块源文件、模块专属配置与其测试由对应 owner 维护；公共编排和入口由 A 维护。共享契约变更须走 `change-request`。
- 跨模块传递只使用 arch.md 定义的数组、配置映射和明确的指标输入；不得传递模块内部对象、全局状态或隐式单例。
- `PipelineResult` 等入口返回类型只用于 core 与 CLI/UI 之间，不得被算法模块用作相互通信对象。

### 3.4 参数、命名与路径

- 用户可调算法参数必须来自 `config/` 下对应模块配置；数学常量可留在源码中，但须命名并说明用途。
- 文件、函数和变量使用 `snake_case`；模块名与职责对应。
- 禁止硬编码机器绝对路径；路径以仓库根目录为基准或通过 CLI/UI 输入提供。

## 4. 禁止事项

### 4.1 UI 侧

- 禁止使用 emoji、大面积渐变背景或超过两种设计字体。
- 禁止深色背景配纯黑文字、未登记色值/字号、低对比度文字或仅靠颜色传达状态。
- 禁止拉伸/裁切输入图；禁止在处理失败或状态未知时展示成似乎成功的结果。

### 4.2 算法/代码侧

- 禁止使用深度学习或任何预训练模型。
- 禁止模块间直接调用/导入私有函数或全局状态。
- 禁止算法模块直接读写文件、修改 UI 状态或原地覆盖输入图。
- 禁止硬编码机器绝对路径及可调算法参数。
- 未经 `change-request` 评审，禁止改变公共接口、掩码格式或配置契约。
- 禁止将受许可约束的 CelebAMask-HQ 原始图像、掩码或数据集内容提交到仓库。
